# Drug Edu

Drug Edu is an Android-focused clinical pharmacist workspace for practical medication counseling, medication-use technique, medication planning, enteral-tube administration, supplements and source-locked IV preparation.

## Version 1.0 freeze

Version **1.0.0+1** is the frozen v1.0 baseline for the current project scope. The encyclopedia is considered clinically complete for this scope; future content changes should be driven by meaningful safety, label/IFU, guideline or formulation/device updates, or an explicit expansion request rather than by adding products simply because they exist.

The final v1.0 baseline includes:

- **213 medication/formulation records** in the counseling encyclopedia.
- **213/213 Arabic patient-counseling coverage** with resolved practical timing, missed-dose guidance, red flags and teach-back.
- **213/213 reviewed English patient-counseling records**. English is not generated by automatic clinical translation fallback.
- Explicit patient-facing **therapy duration** and **medication-plan timing coverage** for every medication record.
- A multi-medication patient plan with interaction, duplication and unsafe-auto-scheduling safeguards.
- **45 source-locked Feeding Tube / NG medication-formulation records**, including explicit do-not-crush/do-not-tube restrictions and product-specific tube methods.
- **133 source-locked structured IV preparation profiles** matched one-to-one with the structured IV catalog. The calculators convert a prescribed order; they do not choose a therapeutic dose.
- **37 supplement profiles** with practical use, formulation/salt distinctions and lab/interaction checkpoints.
- **19 source-locked nebulizer preparation profiles** with ready-to-use/concentrate, diluent, mixing and device locks.
- Device/technique content for inhalers, nebulizers, nasal sprays, eye/ear products, injections and Visual Guides.
- General, pediatric, NICU and PICU content where supported by the exact source/formulation.

## Clinical safety rules

- Formulation, brand/device and route-specific instructions are not generalized to another product.
- A tablet being crushable orally does not prove feeding-tube compatibility.
- Adult preparation or flush volumes are not scaled down for neonates by guesswork.
- Injectable products are not considered enterally safe unless an authoritative source supports the exact product/route.
- Structured IV records require an exact verified preparation profile before the app exposes preparation calculations.
- Product-specific storage, crushing/opening, missed-dose and administration locks are regression-tested where clinically important.
- The medication plan blocks automatic clock-time scheduling when the exact formulation, indication, meal choice or regimen requires manual review.
- The app is a professional reference and counseling aid; it does not replace patient-specific prescribing, diagnosis, institutional sterile-compounding policy or clinical monitoring.

## App structure

Primary navigation is intentionally compact:

- Home
- Encyclopedia
- IV Prep
- Calculators
- More

Feeding Tubes, Supplements, Visual Guides and Patient Cards remain integrated within the main app rather than being separate applications.

## Quality gates

Every pull request is expected to pass the full Flutter CI pipeline:

```bash
flutter analyze
flutter test
flutter build apk --debug
flutter build apk --release
flutter build appbundle --release
```

CI also uploads a Debug APK artifact and a release-candidate artifact containing the Release APK, Release AAB and signing-status file.

The v1.0 freeze regression suite locks the medication count, bilingual counseling coverage, therapy-duration coverage, medication-plan timing coverage, family IDs, Visual Guide references, Feeding Tube uniqueness/source fields, supplement and nebulizer uniqueness, IV profile/catalog one-to-one consistency, unsafe auto-scheduling safeguards and release-blocking placeholder text.

## Android identity and release

The Android application ID is:

```text
com.mustafagfx97.drug_edu
```

The visible app name is **Drug Edu**.

For Google Play, an **Android App Bundle (AAB)** is the preferred release artifact. Production publication requires an upload keystore; keystore files and passwords must never be committed to the repository. The release workflow supports GitHub Actions secrets for production signing and otherwise produces a clearly marked non-store release candidate.

Required production-signing secrets:

- `ANDROID_KEYSTORE_BASE64`
- `ANDROID_KEYSTORE_PASSWORD`
- `ANDROID_KEY_ALIAS`
- `ANDROID_KEY_PASSWORD`

See `docs/ANDROID_RELEASE.md` for the exact release process.

## Local development

Install current Flutter stable, then run:

```bash
flutter pub get
flutter analyze
flutter test
flutter run
```

The CI pipeline regenerates the Android wrapper from the Flutter stable toolchain using `--org com.mustafagfx97`, then verifies the application ID and visible app label before every build. This avoids committing generated platform binaries while keeping the Android identity reproducible.

## Maintenance after v1.0

Routine maintenance should focus on clinically meaningful changes: safety communications, label/IFU changes, guideline updates and formulation/device differences. A periodic review cadence can be used to detect those changes without reopening broad product expansion.
