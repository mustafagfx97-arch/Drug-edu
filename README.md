# Drug Edu

Drug Edu is an Android-focused clinical pharmacist workspace for practical medication counseling, medication-use technique, medication planning, enteral-tube administration, supplements and source-locked IV preparation.

## Version 1.0 clinical scope

The current production-readiness baseline includes:

- **197 medication/formulation records** in the counseling encyclopedia.
- **197/197 explicit Arabic patient-counseling records** with actionable timing, missed-dose guidance, red flags and teach-back.
- **197/197 explicit reviewed English patient-counseling records**. English is never generated by automatic clinical translation fallback.
- Explicit patient-facing **therapy duration** and **medication-plan timing rules** for every medication record.
- A multi-medication patient plan with interaction and duplication safety checks.
- **45 source-locked Feeding Tube / NG medication-formulation records**, including explicit do-not-crush/do-not-tube restrictions and product-specific tube methods.
- **133 source-locked structured IV preparation profiles**. The calculators convert a prescribed order; they do not choose a therapeutic dose.
- **37 supplement profiles** with practical use, lab/interaction checkpoints and vitamin-D support.
- **19 source-locked nebulizer preparation profiles** with exact ready-to-use/concentrate, diluent, mixing and device locks.
- Device/technique content for inhalers, nebulizers, nasal sprays, eye/ear products, injections and visual guides.
- General, pediatric, NICU and PICU content where supported by the exact source/formulation.

## Clinical safety rules

- Formulation, brand/device and route-specific instructions are not generalized to another product.
- A tablet being crushable orally does not prove feeding-tube compatibility.
- Adult preparation or flush volumes are not scaled down for neonates by guesswork.
- Injectable products are not considered enterally safe unless an authoritative source supports the exact product/route.
- Structured IV records require an exact verified preparation profile before the app exposes preparation calculations.
- High-risk timing, interaction and formulation rules are regression-tested.
- The app is a professional reference and counseling aid; it does not replace patient-specific prescribing, diagnosis, institutional sterile-compounding policy or clinical monitoring.

## App structure

Primary navigation is intentionally compact:

- Home
- Encyclopedia
- IV Prep
- Calculators
- More

Feeding Tubes, Supplements, Visual Guides and Patient Cards remain integrated within the main app rather than being separate applications.

## Quality gates

Every pull request must pass:

```bash
flutter analyze
flutter test
flutter build apk --debug
```

The release-readiness suite additionally locks the medication count, bilingual coverage, therapy-duration coverage, medication-plan timing coverage, supplement uniqueness, Feeding Tube uniqueness/source fields, IV profile/catalog consistency and visual-guide uniqueness.

## Android identity and release

The Android application ID is:

```text
com.mustafagfx97.drug_edu
```

The visible app name is **Drug Edu**.

For Google Play, an **Android App Bundle (AAB)** is the preferred release artifact. Production publication requires an upload keystore; keystore files and passwords must never be committed to the repository. The release workflow supports GitHub Actions secrets for production signing and also produces a clearly marked non-store release candidate when production signing secrets are absent.

Required production-signing secrets:

- `ANDROID_KEYSTORE_BASE64`
- `ANDROID_KEYSTORE_PASSWORD`
- `ANDROID_KEY_ALIAS`
- `ANDROID_KEY_PASSWORD`

See `docs/ANDROID_RELEASE.md` for the exact release process.

## Local development

Install current Flutter stable, then run:

```bash
flutter pub get
flutter analyze
flutter test
flutter run
```

The CI pipeline regenerates the Android wrapper from the pinned Flutter stable toolchain using `--org com.mustafagfx97`, then verifies the application ID and visible app label before every build. This avoids committing generated platform binaries while keeping the Android identity reproducible.
